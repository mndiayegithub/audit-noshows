## Tasks

### Task 1 — Code JS du nœud n8n `Aggregate Par Mois`

**File :** `.planning/phases/phase-03-n8n-stats-par-mois/n8n-code-node-stats-par-mois.js`

**Shape attendu (requirement 1-4 SPEC) :**
- Input : accès aux items du nœud précédent via `$input.all()` ou `items` (selon convention n8n). Chaque item contient au minimum `date_rdv` (string ISO `YYYY-MM-DD` ou `YYYY-MM-DDTHH:mm:ss`) et `status` (string — no-show si ∈ `["no_show", "NoShow", "Non honoré", "Absent"]`, à confirmer sur le workflow existant).
- Output : un item unique `{ json: { stats_par_mois: [...] } }` que le nœud suivant merge dans l'objet `stats`.
- Algorithme :
  1. Single-pass sur les items → Map `YYYY-MM` → `{ total_rdv: 0, no_shows: 0 }`.
  2. Clé = `item.date_rdv.slice(0, 7)` (pas de `new Date()`, pas de conversion TZ).
  3. Incrémenter `total_rdv` pour chaque ligne ; incrémenter `no_shows` si `isNoShow(item.status)`.
  4. Après le pass, calculer min/max des clés → générer la série complète (gaps zero-filled) via itération mois-par-mois.
  5. Mapper en `{ mois, total_rdv, no_shows, taux }` avec `taux = total_rdv > 0 ? Math.round(no_shows / total_rdv * 1000) / 10 : 0`.
  6. Trier ascendant (ordre lexicographique YYYY-MM = ordre chronologique).
- Edge cases :
  - CSV vide → `stats_par_mois: []`
  - Toutes lignes sur un seul mois → 1 bucket
  - `date_rdv` invalide/null → skip la ligne (ne compte pas dans `total_rdv`)
- Helper `nextMonth("YYYY-MM") → "YYYY-MM"` inline (pas de dépendance externe, n8n Code node = JS vanilla ES2020 sans npm).

**Verification :** relecture du fichier, mental test sur 3 scénarios :
- CSV vide → `[]`
- CSV 3 lignes toutes nov 2025 → `[{mois:"2025-11", total_rdv:3, no_shows:?, taux:?}]`
- CSV couvrant nov+déc 2025 + fév 2026 (pas de jan 2026) → 4 buckets avec `2026-01` à zéros

## Risks & Mitigations

- **Risque :** shape de l'item n8n inconnue (quelles clés exactement pour `status` ?) → **mitigation :** normaliser via un set `NO_SHOW_STATUSES` paramétrable en tête du fichier, que l'utilisateur adaptera au moment de l'import selon ce qu'il voit dans son workflow.
- **Risque :** le nœud `Aggregate Par Mois` pourrait ne pas merger proprement dans `stats` selon la structure du workflow existant → **mitigation :** l'output du nœud est un item autonome `{stats_par_mois: [...]}` ; l'utilisateur a la latitude de merger via expression `{{$json.stats_par_mois}}` dans le nœud assembleur existant, ou via un nœud `Set`/`Merge` suivant. Documenté en Task 3.
- **Risque :** incohérence timezone si Doctolib commence à exporter en UTC → **mitigation :** le `slice(0,7)` sur string brute est volontaire (voir CONTEXT D-08) ; si un jour le format change, ce sera un bug à traiter séparément.
