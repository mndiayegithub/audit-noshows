# Plan 05-01 — Server hardening: validation, logs, rate-limit, CSRF

## Objective
Créer 3 libs (`audit-validation`, `safe-log`, `rate-limit`) et les câbler dans les 2 routes API publiques, avec check origin + logs scrubés + rejet 400/403/429 appropriés.

## Tasks

### Task 1 — `lib/audit-validation.ts`
<read_first>
- app/api/audit/route.ts (signature FormData)
- app/audit/page.tsx (fields envoyés)
</read_first>

<action>
Créer `lib/audit-validation.ts` exportant :
```ts
export type AuditPayload = { csv: string; nom_cabinet: string; ca_moyen: number; email?: string };
export type ValidationResult =
  | { ok: true; values: AuditPayload }
  | { ok: false; error: string };

export function validateAuditPayload(formData: FormData): ValidationResult;
```
Vérifs :
- `csv` string non-vide, ≤ 2_000_000 chars, contient ≥ 2 lignes
- première ligne (séparateur auto `,` ou `;`) inclut les en-têtes `date` ET `statut` (case-insensitive après trim)
- `nom_cabinet` : string trim non-vide, ≤ 120 chars
- `ca_moyen` : `Number(x)` fini, > 0, ≤ 10000
- `email?` : si présent, match `/^[^\s@]+@[^\s@]+\.[^\s@]+$/` ET longueur ≤ 254
Retour `{ ok: false, error }` sur premier fail, sinon `{ ok: true, values }`.
</action>

<acceptance_criteria>
- `grep -n "export function validateAuditPayload" lib/audit-validation.ts` → 1 match
- mental tests : csv vide → error "vide" ; csv 3Mo → error "volumineux" ; en-tête sans `date` → error "colonnes" ; nom_cabinet "" → error ; ca_moyen=-10 → error ; email "foo" → error ; payload valide → ok:true
</acceptance_criteria>

### Task 2 — `lib/safe-log.ts`
<read_first>
- app/api/audit/route.ts (usage console.error)
- app/api/google-places/route.ts (usage console.error)
</read_first>

<action>
Créer `lib/safe-log.ts` exportant :
```ts
export function logServerError(context: string, err: unknown): void;
```
Impl :
- Extrait `name` et `message` de `err` (Error ou autre)
- Tronque message à 200 chars
- Regex-redact : emails `/\S+@\S+\.\S+/g` → `[email]`, séquences alphanum mixtes ≥ 20 chars `/\b[A-Za-z0-9_-]{20,}\b/g` → `[redacted]`
- Log final : `console.error(\`[${context}] ${name}: ${sanitized}\`)` (1 seule ligne, pas d'objet stack dump)
</action>

<acceptance_criteria>
- `grep -n "export function logServerError" lib/safe-log.ts` → 1 match
- mental test : `logServerError("x", new Error("contact foo@bar.com clé AIzaSyABCDEFGHIJKLMNOPQRST"))` → log contient `[email]` et `[redacted]`, pas le contenu original
</acceptance_criteria>

### Task 3 — `lib/rate-limit.ts`
<read_first>
- app/api/audit/route.ts
</read_first>

<action>
Créer `lib/rate-limit.ts` :
```ts
export interface RateLimitOptions { max: number; windowMs: number; key: string }
export interface RateLimitResult { allowed: boolean; retryAfterSec?: number }
export function checkRateLimit(request: Request, opts: RateLimitOptions): RateLimitResult;
```
Impl :
- Module-scope `Map<string, { count: number; resetAt: number }>` avec clé `${opts.key}:${ip}`
- IP = `request.headers.get("x-forwarded-for")?.split(",")[0]?.trim() ?? "unknown"`
- Si pas d'entrée ou `Date.now() > resetAt` → créer/reset `{count:1, resetAt: now+windowMs}`, return `{allowed:true}`
- Sinon si `count < max` → incr, return `{allowed:true}`
- Sinon → return `{allowed:false, retryAfterSec: Math.ceil((resetAt-now)/1000)}`
- Wrap en try/catch → fail-open (`{allowed:true}` sur exception)
</action>

<acceptance_criteria>
- `grep -n "export function checkRateLimit" lib/rate-limit.ts` → 1 match
- `grep -n "x-forwarded-for" lib/rate-limit.ts` → 1 match
</acceptance_criteria>

### Task 4 — Câbler dans `app/api/audit/route.ts`
<read_first>
- app/api/audit/route.ts
</read_first>

<action>
En début de `POST(request)` (avant `request.formData()`) :
1. Check origin : `const origin = request.headers.get("origin") || request.headers.get("referer") || ""`. Liste autorisée : contient `"localhost"`, `"127.0.0.1"`, `"vercel.app"`, `"perfiamatic.fr"`. Si `!origin || !allowed.some(d => origin.includes(d))` → `return Response.json({ success: false, error: "Origine non autorisée" }, { status: 403 })`.
2. Rate-limit : `const rl = checkRateLimit(request, { max: 10, windowMs: 600_000, key: "audit" })`. Si `!rl.allowed` → `return Response.json({ success: false, error: "Trop de requêtes, réessayez dans quelques minutes" }, { status: 429, headers: { "Retry-After": String(rl.retryAfterSec ?? 60) } })`.
3. Après `const formData = await request.formData()`, appeler `const v = validateAuditPayload(formData)`. Si `!v.ok` → `return Response.json({ success: false, error: v.error }, { status: 400 })`. Utiliser `v.values` pour construire la requête n8n (reconstruire `formData` ou forward l'original — forward l'original direct est OK car les champs ont été validés tels quels).
4. Remplacer `console.error("Erreur API audit:", error)` par `logServerError("api/audit", error)`.

Ajouter imports en tête : `import { validateAuditPayload } from "@/lib/audit-validation"; import { logServerError } from "@/lib/safe-log"; import { checkRateLimit } from "@/lib/rate-limit";`
</action>

<acceptance_criteria>
- `grep -n "validateAuditPayload\|logServerError\|checkRateLimit" app/api/audit/route.ts` → 4 matches (3 imports + 3 usages = 6 total, accept ≥4)
- `grep -n "console.error" app/api/audit/route.ts` → 0 matches
- `grep -n "Origine non autorisée\|Trop de requêtes" app/api/audit/route.ts` → 2 matches
</acceptance_criteria>
