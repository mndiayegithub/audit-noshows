       ```ts
       interface FixtureParams {
         source: "doctolib" | "excel" | "logos_w" | "julie" | "veasy";
         nb_mois: number;            // durée fictive — utilisée pour le volume
         taux_no_show: number;       // 0..1
         encoding: "utf-8" | "latin-1";
         separator: "," | ";";
         statuts: string[];          // override des libellés (ex: Doctolib utilise "Honoré"/"Excusé"/"Non honoré")
         include_meta_header: boolean;  // ligne "Export du JJ/MM/AAAA" avant header (Doctolib quirk)
         corrupt_pct: number;        // % lignes invalides (date pourrie, statut "DNA", etc.)
         outFile: string;            // ex: "doctolib_6mois.csv"
         expected: "ok" | "degraded" | "reject:MISSING_COLUMNS" | "reject:INSUFFICIENT_DATA" | "reject:ENCODING_ERROR" | "reject:INVALID_DATE_FORMAT" | "reject:EMPTY_AFTER_PARSING";
       }
       ```
    4. Logique du générateur (squelette) :
       - Calcul du nombre total de RDV : `nb_mois * 80` (proxy : 80 RDV/mois cabinet moyen).
       - Header selon source :
         - `doctolib` → `Date,Heure,Praticien,Patient,Statut`
         - `excel` → libre (`Jour,Heure visite,Nom du soignant,Patient,État RDV`) — colonnes nommées librement mais reconnaissables via regex Plan 07-03.
         - `logos_w` → `date_rdv;heure;praticien;patient;status` (séparateur `;`)
         - `julie` → `Date du rendez-vous;Heure;Praticien;Statut` (FR colonnes longues)
         - `veasy` → `RDV_DATE;RDV_HEURE;PRATICIEN;ETAT` (uppercase)
       - Lignes : générer `total` lignes avec date ISO ou DD/MM/YYYY selon source, statuts puisés dans `statuts` weighted par `taux_no_show` pour les no-shows.
       - Insérer `Math.floor(total * corrupt_pct)` lignes corrompues (statut `"DNA"`, `"Reporté"`, ou date `"01-32-9999"`).
       - Si `include_meta_header`, préfixer 1 ligne `Export du 12/03/2026` avant le header (cas Doctolib).
       - **En-tête de fixture** (commentaires CSV en première ligne) :
         ```
         # source: doctolib
         # expected: ok
         # nb_mois: 6 ; taux_no_show: 0.12 ; encoding: utf-8 ; separator: ,
         ```
         Ces commentaires CSV (préfixe `#`) sont ignorés par papaparse en pratique — vérifier que Papa.parse les skip OU les inclure comme lignes vides (skipEmptyLines + transformHeader). Décision : utiliser un préfixe `// ` non standard et le retirer du fichier d'output, OU mettre les commentaires en clé/valeur dans un fichier sidecar `.meta.json`. **Décision arbitrée :** mettre les commentaires en `# source: ... \n# expected: ...` au tout début du CSV, ET fournir un loader helper `e2e/fixtures/loadFixture.ts` (créé en Task suivante du Plan 07-08) qui split les lignes `#` du body. Ne pas modifier papaparse en prod — les fixtures de prod n'auront pas ces commentaires.
       - Encoding : si `latin-1`, écrire avec `Buffer.from(content, "latin1")` puis `fs.writeFileSync(path, buf)`.
    5. Bloc `main()` à la fin du script qui appelle 12+ fois `generate()` avec les params suivants (verrouillés pour reproducibilité) :
       - `doctolib_6mois.csv` (ok), `doctolib_12mois.csv` (ok), `doctolib_18mois.csv` (ok)
